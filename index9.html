What is the Internet?

Imagine you have a pen-friend in another country. You write a letter, put it in an envelope, and the postal system carries it across cities and borders to reach your friend. The Internet does the same thing — but instead of letters and envelopes, it sends data packets through cables and wireless signals, millions of times per second.

🌍
Real-World Example

When Ravi opens Instagram from his hostel room in Tiruppur, his phone's data travels through Jio's tower → Jio's backbone → Internet cables → Instagram's servers in the USA → back to his phone in milliseconds. That journey is the Internet at work.

World Wide Web (WWW)

The Internet is the road. The WWW (World Wide Web) is the content on those roads — web pages, images, videos, all connected by links. Tim Berners-Lee invented it in 1989 at CERN.

Think of it this way: Internet = Railway network. WWW = the trains and passengers travelling on it.

2-Mark Answer: What is Client-Server Communication?

Client-server communication is a network model where a client (like your browser) sends a request to a server, and the server processes it and returns a response. Example: Your browser (client) requests google.com → Google's server responds with the webpage HTML. It follows the HTTP/HTTPS protocol.

DNS — The Internet's Phone Book

When you type youtube.com, your computer doesn't know what that means — it only understands IP addresses. DNS (Domain Name System) converts human-friendly names into IP numbers, just like how your phone contacts store "Mom" instead of her phone number.

1
You type youtube.comBrowser sends DNS query to your ISP's DNS server
2
DNS LookupDNS server finds the IP address: 142.250.192.46
3
Browser connectsYour browser connects to that IP and loads YouTube
📝
2-Mark Answer: What is Domain Name Space?

Domain Name Space is the hierarchical naming structure used by DNS to organize all domain names on the Internet. It is a tree-like structure with the root at the top, followed by top-level domains (TLD) like .com, .in, .edu, then second-level domains like google.com, and subdomains like mail.google.com. This hierarchy enables efficient and distributed management of billions of domain names worldwide.

Document Object Model (DOM)

When a browser loads your HTML, it creates a tree of objects — one object for each tag. This tree is called the DOM. JavaScript can grab any object in this tree and change it — change the text, change colors, add/remove elements — all without reloading the page.

🌳
DOM Tree Example

HTML → html → head (title) + body (h1, p, div(button, span))
Each tag becomes a "node" in this tree. JavaScript uses document.getElementById() to find any node and manipulate it.

// DOM Manipulation Example
// HTML: <p id="welcome">Hello!</p>
// JS changes the text:
document.getElementById('welcome').innerHTML = 'Welcome, Ravi!';

// Change background color
document.body.style.backgroundColor = '#1a1a2e';

Complete HTML5 Document Structure

Every HTML5 page must have this skeleton. Think of it as the blueprint of a building. Without this structure, the browser might still render things, but it will make guesses — and guesses lead to bugs.

<!DOCTYPE html>        <!-- Required: tells browser = HTML5 -->
<html lang="en">          <!-- Root element, lang helps accessibility -->
<head>                 <!-- Metadata section — NOT visible to users -->
  <meta charset="UTF-8">  <!-- Support all characters/languages -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Sasurie Canteen</title>   <!-- Shown in browser tab -->
  <link rel="stylesheet" href="style.css">  <!-- Link external CSS -->
</head>
<body>                 <!-- Everything here is visible on screen -->
  <h1>Welcome to Sasurie Canteen</h1>
  <p>Today's special: Pongal &amp; Sambar</p>
</body>
</html>
⚠️
Important: Character References (HTML Entities)

&lt; = < (less than sign) | &gt; = > (greater than) | &amp; = & (ampersand) | &copy; = © | &nbsp; = non-breaking space
Use these when you want to display HTML characters as text, not as code.

16MDifferentiate between a Web Server and Application Server. Explain their architecture, functions, and applications with examples.

Introduction: When a user visits a dynamic website, two types of servers may be involved: the Web Server that handles the communication, and the Application Server that processes the business logic.

Web Server: A web server is software/hardware that accepts HTTP requests from clients (browsers) and serves back static content like HTML files, CSS files, images, and JavaScript files. It does not process business logic. Examples: Apache HTTP Server, Nginx, Microsoft IIS.

Application Server: An application server hosts and executes business logic, generates dynamic content by interacting with databases and APIs, and returns the result to the web server. Examples: Apache Tomcat (Java), JBoss, WebLogic, Node.js.

Architecture Comparison:

Web Server → receives HTTP request → serves static file (if available) → passes dynamic requests → Application Server → executes code/queries DB → returns result → Web Server → sends response to Browser.

Real Application Example: In Ravi's Canteen Website: When a student views the static home page (menu.html), the web server (Nginx) serves it directly. When a student submits an order form, the request goes to the Application Server (Tomcat), which processes the order, updates the database, and sends a confirmation back.

Conclusion: Web Servers excel at serving static content efficiently. Application Servers provide the dynamic, interactive features of modern web applications. Most production systems use both together in a layered architecture.

8MExplain the Document Object Model (DOM). Write a JavaScript program to change the content of an HTML element using a button.

DOM Definition: The Document Object Model (DOM) is a programming interface and tree-structured representation of an HTML document. When a browser parses an HTML page, it creates a DOM — a collection of objects, one for each HTML element, arranged in a parent-child hierarchy.

How the DOM Tree Works: HTML → html → head + body → Each tag becomes a node. JavaScript can access any node using methods like document.getElementById(), document.querySelector(), document.getElementsByTagName().

JavaScript Program:

<p id="msg">Original text here</p>
<button onclick="changeText()">Change Text</button>
<script>
function changeText() {
  document.getElementById('msg').innerHTML = 'Text changed by JavaScript!';
}
</script>

Explanation: When button is clicked → changeText() runs → getElementById finds the <p> node in DOM → innerHTML property is updated → Browser re-renders the changed text instantly without page reload.

Unit I — Interview Preparation
Basic → Intermediate → Advanced → Scenario-based
● Basic Level
BasicWhat is the difference between HTTP and HTTPS?

HTTP (HyperText Transfer Protocol) is an unsecured protocol where data is sent as plain text. HTTPS adds a security layer using SSL/TLS encryption, which means all data is encrypted and cannot be read by someone intercepting the traffic. Websites handling passwords or payments must use HTTPS. The padlock icon in your browser indicates HTTPS is active.

BasicWhat is an IP address? What is the difference between IPv4 and IPv6?

An IP address is a unique numerical identifier assigned to every device on a network. IPv4 is 32-bit, written in dotted decimal (e.g., 192.168.1.1), and supports ~4.3 billion addresses — nearly exhausted. IPv6 is 128-bit, written in hexadecimal groups (e.g., 2001:db8::1), and supports a practically unlimited number of devices. Modern networks increasingly use IPv6 to accommodate the growing number of Internet-connected devices.

● Intermediate Level
MediumExplain the complete process of what happens when you type a URL in a browser.

1. URL parsing — Browser breaks URL into protocol, domain, path.
2. DNS lookup — OS checks local cache; if not found, asks ISP's DNS server to resolve domain to IP.
3. TCP connection — Browser opens a TCP connection to the server IP (port 80 for HTTP, 443 for HTTPS).
4. TLS handshake — For HTTPS, SSL certificate is exchanged and encryption is established.
5. HTTP request — Browser sends GET request for the page.
6. Server response — Server sends back HTML, status code 200 OK.
7. Rendering — Browser parses HTML → builds DOM → fetches CSS → applies styles → fetches JS → executes → paints the page.

● Advanced / 3rd Year Level
AdvancedWhat is the difference between the DOM and the actual HTML source code?

The HTML source code is the static text file written by the developer. The DOM is the browser's live, in-memory representation of that HTML as a tree of objects. Key differences: (1) The DOM can be modified by JavaScript at runtime — if JS adds a new <div>, it appears in the DOM but not in the source file. (2) The browser may fix invalid HTML when building the DOM (e.g., auto-add missing <tbody> in tables). (3) "View Source" shows the original file; "Inspect Element" shows the current DOM state. Modern SPAs (like React apps) often have minimal HTML source but a rich, dynamic DOM built entirely by JavaScript.

The CSS Box Model

Every single HTML element is a rectangular box. Understanding the box model is the most important CSS concept. If you master this, you can control the layout of any webpage.

📦
Box Model = Content + Padding + Border + Margin

Content — The actual text or image
Padding — Space inside the border (between content and border)
Border — The visible line around the element
Margin — Space outside the border (pushes other elements away)

.food-card {

CSS Grid Layout — Assignment 1, Q3

What is CSS Grid?

CSS Grid is a two-dimensional layout system that lets you arrange items into rows AND columns at the same time. Flexbox is 1D (either a row OR a column). Grid is 2D (rows AND columns simultaneously).

🗞️
Real-World Analogy

Think of a newspaper layout. Articles are arranged in columns and rows — some articles span multiple columns. CSS Grid lets you create exactly this kind of complex layout with just a few lines of CSS.

/* Grid Container — the parent */
.grid-container {
  display: grid;
  grid-template-columns: 1fr 2fr 1fr; /* 3 columns: 25% | 50% | 25% */
  grid-template-rows: auto auto;       /* 2 rows, height = content */
  gap: 16px;                         /* space between cells */
}

/* Grid Item spanning multiple columns */
.header-item {
  grid-column: 1 / 4;    /* span from column 1 to 4 (full width) */
}

<!-- HTML -->
<div class="grid-container">
  <div class="item">Sidebar</div>
  <div class="item">Main Content</div>
  <div class="item">Ads Panel</div>
</div>

16MExplain the concept of Cascading in CSS. Discuss Inline, Internal, and External Style Sheets with suitable examples.

Introduction: CSS stands for Cascading Style Sheets. The word "Cascading" is key — it describes how the browser resolves conflicts when multiple CSS rules target the same element. The cascade follows a defined priority system.

What is Cascading? When multiple CSS rules apply to the same element, the browser uses three factors to determine the winner: (1) Source order — later rules override earlier ones; (2) Specificity — ID > Class > Tag; (3) !important — overrides everything.

1. Inline CSS: Written directly in the HTML tag using style attribute. Highest specificity. Hard to maintain because styling is mixed with content. Use only for quick overrides.
Example: <p style="color:red; font-size:18px;">Red text</p>

2. Internal CSS: Written inside <style> tags in the <head> section. Applies only to that specific page. Good for page-specific styles. Medium specificity (depends on selector used).
Example: <style> p { color: blue; } </style>

3. External CSS: Written in a separate .css file linked with <link rel="stylesheet" href="styles.css">. Best practice for real projects. One file can style all pages. Cached by browser for performance. Any specificity level depends on selectors used.

Specificity Calculation: ID=100 points, Class=10 points, Tag=1 point. Highest total wins. Example: #header p.highlight = 100+1+10 = 111 points.

Conclusion: Understanding the cascade helps developers predict which styles will be applied and how to override styles correctly without resorting to !important overuse.

● Basic Level
BasicWhat is the difference between margin and padding?

Both create space, but in different places. Padding is the space between the element's content and its border — it's inside the element, so padding area gets the element's background color. Margin is the space outside the border — it separates the element from other elements. Note: vertical margins between adjacent elements collapse to the larger value (margin collapsing). Padding does not collapse.

BasicWhat is specificity in CSS? Give an example.

Specificity is how the browser decides which CSS rule applies when multiple rules target the same element. It's calculated as: ID selectors = 100 points, Class/attribute/pseudo-class = 10 points, Tag/pseudo-element = 1 point. Example: p = 1 point, .text = 10 points, #main = 100 points, #main .text = 110 points. The rule with the highest score wins. If scores are equal, the last rule in the file wins.

● Intermediate Level
MediumWhen would you use Flexbox vs CSS Grid?

Use Flexbox when you need to lay out items in a single direction (a row of buttons, a horizontal nav bar, centering a single item). Flexbox is "content-first" — it works from the content outward. Use CSS Grid when you need to control both rows AND columns simultaneously (a dashboard, a photo gallery, a page layout with header/sidebar/main/footer). Grid is "layout-first" — you define the grid structure first, then place items into it. In modern web development, both are often used together: Grid for the page layout, Flexbox for components within each grid cell.

ScenarioA Bootstrap website looks broken on mobile. Where do you start debugging?

JavaScript interview questions — 2nd year and 3rd year levels
● Basic Level (2nd Year)
BasicWhat is the difference between == and === in JavaScript?

== (loose equality) compares values after type conversion. For example, 5 == "5" is true because the string "5" is converted to number before comparing. === (strict equality) compares both value AND type without any conversion. 5 === "5" is false because one is a number and the other is a string. Always prefer === in modern JavaScript to avoid unexpected type coercion bugs.

BasicWhat is jQuery's $(document).ready() used for?

$(document).ready() ensures that the JavaScript code inside it runs only after the complete HTML document has been loaded and the DOM is ready to be manipulated. Without it, if JavaScript tries to access a DOM element before the browser has created it, the result is null and the code fails. It's like waiting for a house to be built before trying to paint the walls. Modern equivalent: place <script> at the bottom of <body>, or use the defer attribute on the script tag.

● Intermediate Level (3rd Year)
MediumExplain event bubbling and event delegation in JavaScript.

Event Bubbling: When an event occurs on an element, it first runs the event handlers on that element, then on its parent, then grandparent, all the way up to the document root. Example: clicking a button inside a div will trigger the button's onclick, then the div's onclick, then body's, etc. Event Delegation: Instead of adding event listeners to each child element, you add one listener to the parent and check event.target to know which child was clicked. This is efficient when you have many items (like a menu list) or dynamically added elements. Example: Add one onclick to <ul> and check if event.target is a <li>.

MediumWhat is JSON and why is it preferred over XML for data exchange in web apps?

JSON (JavaScript Object Notation) is a lightweight text format for data exchange based on JavaScript object syntax. XML is an older markup language also used for data exchange. JSON is preferred because: (1) JSON is more compact — less verbose than XML (no opening/closing tags); (2) JSON parses directly into JavaScript objects (JSON.parse()); (3) JSON is easier to read for developers; (4) JSON is natively supported in all modern browsers; (5) Most REST APIs return JSON. The only advantage XML has: XML supports comments, has better schema validation, and is used in some legacy enterprise systems (SOAP, RSS/Atom feeds).

● Advanced / Tricky Questions
AdvancedWhat is the difference between innerHTML and textContent?

Both read or set the content of a DOM element, but with an important difference. innerHTML reads/writes the HTML markup inside an element — it will parse HTML tags. Setting innerHTML to '<b>Hello</b>' renders bold text. It can be a security risk (XSS attack) if user input is directly inserted without sanitization. textContent reads/writes only plain text — it ignores HTML tags and treats them as literal characters. Setting textContent to '<b>Hello</b>' displays the text <b>Hello</b> literally. Use textContent when inserting user-provided data to prevent XSS attacks. Use innerHTML when you intentionally need to render HTML structure.
