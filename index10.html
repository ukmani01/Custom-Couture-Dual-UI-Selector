01 / BROWSER

What is a web browser?

Think of the browser as your window into the web. It accepts an address, communicates with servers and turns the returned HTML, CSS and JavaScript into the page you see.

●
https://college.example/hostel
↻
HOSTEL HUB
Good evening, student.
View Mess Menu
1. You enter a URL

Example: college.example/hostel

2. Browser sends a request

It asks the appropriate server for the resource or data.

3. Server sends a response

The response can contain HTML, CSS, JavaScript or data such as JSON.

4. Browser renders the result

It interprets the response and displays an interactive interface.

02 / CLIENT–SERVER

How does communication happen?

Everyday web actions follow a simple pattern: Request → Processing → Response.

01UserClick / type / submit
02BrowserCreates HTTP request
03ServerProcesses request
04ResponseData travels back
05BrowserUpdates the screen
REQUEST GET /hostel/menu

“Server, please give me today's menu.”

→
RESPONSE 200 OK

“Here is today's menu data.”

HTTP

The communication protocol

HTTP defines how requests and responses are exchanged between clients and servers.

REQUEST

What the client asks for

Method, URL, headers and sometimes a body containing data.

RESPONSE

What the server sends back

Status code, headers and content such as HTML or JSON data.

03 / BACKEND SERVICES

Imagine a hostel server.

A real server is not “one magical program”. A web application can contain multiple backend services, each responsible for a specific job.

REAL-WORLD ANALOGY

Hostel = Web Application

When you ask the hostel office for something, the request goes to the right person or department. A web server works in a similar way.

One hostel → many services → one student experience.
