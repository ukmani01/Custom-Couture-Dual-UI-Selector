4. Database Design

This section details the database architecture of the Custom Couture Web Application.

4.1 Database Relationships

User to Orders Relationship

User
1 : N
Order

Explanation: A User can place multiple Orders. Each Order belongs to exactly one User. This is a one-to-many (1:N) relationship.

User to Measurements Relationship

User
1 : 1
Measurement

Explanation: Each User has exactly one Measurement record. The UNIQUE constraint on user_id enforces this one-to-one (1:1) relationship.

Complete Entity Flow

User
Order
Measurement

Explanation: The complete flow shows that a User has Orders (one-to-many) and Measurements (one-to-one). The UNIQUE constraint on user_id in the Measurements table ensures each user has only one measurement record.

4.3 Design Decisions

DecisionReasoning
SQLite vs MySQLSQLite was chosen because this is a development/demonstration application. It requires no separate server installation, uses a single file for storage, and provides ACID compliance. For production scaling, migration to PostgreSQL would be recommended.
Relational vs NoSQLRelational schema is appropriate because data has clear relationships (User → Orders, User → Measurements). Foreign key constraints ensure data integrity. NoSQL would be overkill for this domain model.
Why separate models.pySeparating models into their own file improves code organization, makes the schema easier to understand, and allows models to be imported by multiple files without circular imports.
Measurement UNIQUE constraintEnsures each user has only one measurement record. Prevents duplicate measurements without application-level logic.
Status field in OrderEnables order lifecycle tracking without separate state table. Values: Pending → Processing → Completed.
Handler field in OrderAllows assignment of orders to specific tailors/workshops. Enables workload distribution.
Priority field in OrderEnables VIP/urgent order handling. 0=Normal, 1=VIP/Urgent.
Separate Inventory tableEnables stock tracking independent of orders. Prevents overselling.

Explanation: When a user views their dashboard, the system checks if they have previous orders. If yes, personalized suggestions are generated. If no, default recommendations are shown instead. This helps users discover new styles.

6. Algorithms (Pseudocode)

This section presents the key algorithms used in the Custom Couture Web Application in structured pseudocode format.

6.1 User Registration Algorithm

Algorithm: Register User
Inputs: name, email, password, phone (optional)
Outputs: Success – auto-login redirect to dashboard; Failure – redirect to registration with error

Procedure:
1. IF request.method == 'POST':
2.   name ← request.form.get('name')
3.   email ← request.form.get('email')
4.   password ← request.form.get('password')
5.   phone ← request.form.get('phone', '')
6.   Validate required fields:
7.   IF name, email, or password is empty:
8.     flash("All fields are required.", "danger")
9.     RETURN redirect(url_for('register'))
10.  Check for duplicate email:
11.  existing ← User.query.filter_by(email = email).first()
12.  IF existing is not NULL:
13.    flash("Email already registered.", "danger")
14.    RETURN redirect(url_for('register'))
15.  Create user object:
16.  user ← new User(name=name, email=email, password=password, phone=phone)
17.  Persist to database:
18.  db.session.add(user); db.session.commit()
19.  Auto-login:
20.  session['user_id'] ← user.id
21.  flash("Account created!", "success")
22.  RETURN redirect(url_for('dashboard'))
23. RETURN render_template('register.html')

Time Complexity: O(1) for email check (indexed), O(1) for insert.

6.2 User Login Algorithm

Algorithm: Authenticate User
Inputs: email, password
Outputs: Success – session set, redirect to dashboard; Failure – display error, stay on login

Procedure:
1. IF request.method == 'POST':
2.   email ← request.form.get('email')
3.   password ← request.form.get('password')
4.   Query database:
5.   user ← User.query.filter_by(email = email).first()
6.   Verify credentials:
7.   IF user is not NULL AND user.password == password:
8.     session['user_id'] ← user.id
9.     flash("Login successful!", "success")
10.    RETURN redirect(url_for('dashboard'))
11.  ELSE:
12.    flash("Invalid credentials.", "danger")
13.    RETURN redirect(url_for('login'))
14. RETURN render_template('login.html')

Time Complexity: O(1) with email index, O(1) password comparison.
⚠️ Warning: Password should be hashed using bcrypt/werkzeug for production security.

6.3 Price Calculation Algorithm

Algorithm: Calculate Outfit Price
Inputs: fabric, sleeve, embroidery
Outputs: total_price (base + additions)

Procedure:
1. base_price ← 5000
2. extras ← 0
3. Dictionary lookups for pricing:
4. fabric_prices ← {'Cotton':0, 'Silk':1500, 'Satin':1000, 'Lace':2000, 'Velvet':1800}
5. sleeve_prices ← {'Sleeveless':0, 'Cap Sleeve':200, 'Short Sleeve':300, 'Elbow Length':400, 'Full Sleeve':500}
6. embroidery_prices ← {'None':0, 'Floral':1500, 'Beadwork':2500, 'Sequin':2000}
7. extras ← extras + fabric_prices.get(fabric, 0)
8. extras ← extras + sleeve_prices.get(sleeve, 0)
9. extras ← extras + embroidery_prices.get(embroidery, 0)
10. RETURN base_price + extras

Time Complexity: O(1) – constant time dictionary lookups.
💡 Tip: Dictionary provides O(1) lookups, easily extensible, centralized pricing logic.

6.4 Recommendation Generation Algorithm

Algorithm: Generate Outfit Recommendations
Inputs: user_id
Outputs: recommendations (list of 3 recommendation objects)

Procedure:
1. last_order ← Order.query.filter_by(user_id=user_id).order_by(Order.created_at.desc()).first()
2. IF last_order is not NULL:
3.   fabric_map ← {...}  // similar fabric mappings
4.   silhouette_map ← {...}
5.   suggested_fabrics ← fabric_map.get(last_order.fabric, ['Silk','Satin'])
6.   suggested_silhouettes ← silhouette_map.get(last_order.silhouette, ['A-Line','Mermaid'])
7.   recommendations ← []
8.   FOR i = 1 TO 3:
9.     rec ← new Recommendation()
10.    rec.name ← "Style " + i
11.    rec.silhouette ← random.choice(suggested_silhouettes)
12.    rec.neckline ← random.choice(['V-Neck','Sweetheart','Boat Neck'])
13.    rec.sleeve ← random.choice(['Sleeveless','Cap Sleeve','Full Sleeve'])
14.    rec.fabric ← random.choice(suggested_fabrics)
15.    rec.color ← random.choice(['#c9a84c','#e74c3c','#2c3e50','#1abc9c'])
16.    rec.embroidery ← random.choice(['None','Floral','Beadwork'])
17.    rec.image_icon ← random.choice(['👗','👘','🧥','👚'])
18.    recommendations.append(rec)
19.   RETURN recommendations
20. ELSE:
21.   RETURN default recommendations (Elegant A-Line, Bold Mermaid, Classic Sheath)

Time Complexity: O(1) for dictionary lookups, O(3) for generating recommendations.
Note: Simple rule-based recommendation works without ML; maps provide extensibility.

6.5 Inventory Update Algorithm

Algorithm: Update Inventory After Order
Inputs: fabric_name, quantity_change (negative for deduction)
Outputs: success (boolean), updated_quantity

Procedure:
1. item ← Inventory.query.filter_by(fabric_name = fabric_name).first()
2. IF item is NULL: RETURN False
3. item.quantity ← item.quantity + quantity_change
4. IF item.quantity > 0: item.availability ← True
5. ELSE: item.availability ← False
6. db.session.commit()
7. RETURN True

Time Complexity: O(1) – single database query and update.

6.6 Admin Authorization Algorithm

Algorithm: Authorize Admin Access
Inputs: user_id (from session)
Outputs: true (admin), false (redirect to appropriate page)

Procedure:
1. IF 'user_id' NOT IN session:
2.   flash("Please login first.", "danger")
3.   RETURN redirect(url_for('login'))
4. user ← User.query.get(session['user_id'])
5. IF user.email != 'admin@admin.com':
6.   flash("Admin access required.", "danger")
7.   RETURN redirect(url_for('dashboard'))
8. RETURN True

6.7 Order Submission Validation

Algorithm: Validate Order Submission
Inputs: silhouette, neckline, sleeve, fabric
Outputs: valid (boolean), error_message

Procedure:
1. IF silhouette is empty OR neckline is empty OR sleeve is empty OR fabric is empty:
2.   flash("All design fields are required.", "danger")
3.   RETURN redirect(url_for('builder'))
4. RETURN True

Time Complexity: O(1)

6.8 Database Retrieval for Dashboard

Algorithm: Get User Dashboard Data
Inputs: user_id
Outputs: user, orders, measurement, recommendations

Procedure:
1. user ← User.query.get(user_id)
2. orders ← Order.query.filter_by(user_id = user_id).order_by(Order.created_at.desc()).all()
3. measurement ← Measurement.query.filter_by(user_id = user_id).first()
4. recommendations ← get_recommendations(user_id)
5. RETURN user, orders, measurement, recommendations

Time Complexity: O(n) where n = number of orders for user.

6.9 API Price Calculation

Algorithm: API Price Calculation
Inputs: fabric, sleeve, embroidery (JSON)
Outputs: price (JSON)

Procedure:
1. data ← request.get_json()
2. fabric ← data.get('fabric', 'Silk')
3. sleeve ← data.get('sleeve', 'Sleeveless')
4. embroidery ← data.get('embroidery', 'None')
5. price ← calculate_price(fabric, sleeve, embroidery)
6. RETURN jsonify({'price': price})

Time Complexity: O(1)

6.10 Order Status Update

Algorithm: Update Order Status
Inputs: order_id, new_status
Outputs: Success – status updated; Failure – invalid status

Procedure:
1. valid_statuses ← ['Pending', 'Production', 'Ready', 'Delivered']
2. order ← Order.query.get_or_404(order_id)
3. IF new_status NOT IN valid_statuses:
4.   flash("Invalid status.", "danger")
5.   RETURN redirect(url_for('admin'))
6. order.status ← new_status
7. db.session.commit()
8. flash("Order #" + order_id + " status updated to " + new_status + ".", "success")
9. RETURN redirect(url_for('admin'))

Time Complexity: O(1)

def calculate_price(fabric, sleeve, embroidery):
    base_price = 5000
    extras = 0
    fabric_prices = {'Cotton':0, 'Silk':1500, 'Satin':1000, 'Lace':2000, 'Velvet':1800}
    sleeve_prices = {'Sleeveless':0, 'Cap Sleeve':200, 'Short Sleeve':300, 'Elbow Length':400, 'Full Sleeve':500}
    emb_prices = {'None':0, 'Floral':1500, 'Beadwork':2500, 'Sequin':2000}
    extras += fabric_prices.get(fabric, 0)
    extras += sleeve_prices.get(sleeve, 0)
    extras += emb_prices.get(embroidery, 0)
    return base_price + extras

11.12 Custom Jinja Filter (Number Formatting)

@app.template_filter('toLocaleString')
def to_locale_string(value):
    """Format a number with thousand separators (e.g., 5000 -> 5,000)."""
    if value is None:
        return "0"
    try:
        return f"{int(value):,}"
    except (ValueError, TypeError):
        return str(value)
